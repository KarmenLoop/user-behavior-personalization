# 隐私与记忆控制 — v0.3.0

[English](privacy-and-memory-control.md) · [中文](privacy-and-memory-control.zh-CN.md)

档案是私有的协作数据，不授予执行权限，也不能揭示一个人的内心状态。

## 采集与授权

默认不开启观察，需要操作者设置 `--enable-observations`。宿主负责取得本人授权、绑定正确用户、仅传入获授权的反馈。开关是技术配置，不是法律同意证明。适配器只接受有限维度和值，不爬取会话、监视屏幕、记录按键或采集浏览历史。

助手输出、引用他人、沉默、推测的情绪、伪造会话，都不能算用户证据。不要推断健康诊断或敏感身份属性。来源 ID、场景、规则和摘要中也不能夹带密钥或无关隐私。字段结构化能减少存储，但不等于任意输入都是安全的。

## 存储与宿主暴露范围

`--root` 应位于公开仓库外。本地文件在系统支持时设置限制权限；Windows 仍需合适的用户与 ACL 配置。SQLite 不提供这里所需的加密层。共享本地账号可以访问该账号有权读取的文件，subject 命名空间不能替代操作系统隔离。

`profile_read` 将选择的已确认规则交给宿主。远端模型可能按宿主和提供方自己的网络、留存策略接收到规则与任务。`build_context.py` 不执行发送，但重定向的 stdout 包含私有请求内容；发送前应检查目的地。

v0.3.0 包装入口将模型输出流向终端，只保留元数据收条，不落盘原始提示或输出。终端录制、宿主日志、外部导出、提供方历史和备份均是独立副本。v0.2.0 的 `host-runs` 可能包含未绑定用户的原始输出，应核实归属和保留需要后，另行手动清理。

## 查看与纠正

用 `profile_export` 查看实际档案，暂停期间也可操作。用 `profile_insights` 区分观察、候选和已确认规则。应描述“三个会话支持代码审查采用此格式”，而不是给用户贴人格标签。

纠正需要当前版本与真正的新来源。明确指令优先于推断偏好。没有结构化维度的自由文本规则仍可能需要人工处理冲突；系统不会进行语义心理诊断。

## 暂停

`profile_pause` 停止普通检索、观察和候选采用，导出与删除仍可用。暂停不会删除已有内容，重置和遗忘另行操作。移除观察开关只会阻止新增采集，不会自动抹掉旧观察。

## 删除与防止重建

| 操作 | 删除的受控内容 |
|---|---|
| `profile_forget` | 指定规则、历史、关联学习证据、受控导出与用户收条。结构化规则会清除该场景/维度的证据，避免旧同会话观察重新显现；全局结构化规则覆盖所有场景的该维度。 |
| `profile_forget_observations` | 指定观察及依赖它的已学习规则/历史；为防止复活，还会清理受影响已学习规则对应场景/维度的证据。 |
| `profile_reset` | 档案内容和受控产物，结束时保持暂停。 |

适配器保留最小来源哈希来抑制重放。它仍是与用户有关的元数据，不是被遗忘的文本，也不代表已经匿名化。不要更换 ID 重新导入旧来源。确需删除整个数据根时，应先停止全部写入者，并确定宿主如何避免再次导入旧历史。

删除不承诺物理 SSD 擦除，也不代表外部副本已经删除。适配器无法删除未受其控制的提供方会话、截图、复制出去的导出或其他备份。

## 共享与同步

同机共享存储需要合适的文件权限和每个 subject 的可信映射。群聊可以采用风格偏好，但不能因此公开私有来源；是否合适由宿主判断。名字相似不能证明两个账号属于同一人。本版本未提供跨设备同步服务。

个性化应减少沟通成本，保留事实分歧和用户选择，不应利用脆弱性、制造依赖或隐藏重大决定。

## 本地进程可见性

Codex 通过 stdin 接收组合后的提示。当前 Cursor CLI 路径使用位置参数，同一系统用户运行的其他工具可能在进程参数中看到内容。如不能接受这层暴露，应使用 MCP 路径或合适的本地账号隔离。输出仍可能被终端或宿主记录；适配器只留元数据，并不会删除那些独立副本。
