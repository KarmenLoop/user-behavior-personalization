# 验收 — v0.4.0

[English](evaluation.md) · [中文](evaluation.zh-CN.md)

对话导入、审查、持久化和删除是可执行的本地能力。后续请求预测仍是**实验性词法检索**，覆盖有限。存储正确、单元测试通过，不等于系统已经理解一个人。

## 包含漏检的质量结果

| 评估阶段 | 实际结果 | 如何解读 |
|---|---|---|
| 初始 11 条预测诊断 | 11 条全部暂不建议，漏掉全部 6 个应建议正例；5 个负例正确暂不建议 | 初版未覆盖预期正例，失败记录保留。 |
| 通用开发改进后的原始集合 | 6 条正确建议、5 条正确暂不建议 | 原集合上的开发对照，不是新一轮独立泛化证据。 |
| 新的、此前未见的 18 条留出查询 | 12 个正例中正确建议 4 个，另 8 个暂不建议；6 个负例全部正确暂不建议 | 正例覆盖率 **33.3%**；英文 **0/6**，中文 **4/6**。 |
| 明确表达提取，20 个案例 | 7 个真正例、0 个假正例、1 个漏检 | 小规模正例集合召回 **7/8 = 87.5%**，一种应支持表达仍被漏掉。 |

新集合中提出的 4 条建议都正确，但 **4/4 不是“总体准确率 100%”的证据**，因为大多数正例没有被提出。输出条件下准确率、覆盖率、暂不建议要一起报告。未进行用户满意度、心理学或教学效果研究。

实现调整使用单独开发例子，不使用新的留出查询。冻结清单绑定数据集和固定时钟；初始失败、开发对照、新留出是不同记录。汇总见[已清理的结果摘要](evaluation-results-v0.4.0.json)。

作为对照，基线方法直接选择当前场景中出现最多、带人工类别标记的后续请求。新留出集上，它给出 16 次建议，其中 12 次正确、4 次误报；连同正确弃权，总计答对 14/18，当前预测器为 10/18。预测器避开了这些误报，但也漏掉了更多合理建议。这个带标记的基线仅供比较，结果不支持声称当前方法整体更强。

## 复现本地行为

在包内使用 Python 3.11+：

```sh
python3 -B scripts/check_package.py
python3 -B -m unittest discover -s tests -v
python3 -B scripts/check_publication.py
python3 -B scripts/demo_conversations.py --root ../new-conversation-acceptance
```

演示以合成文本执行真实本地 CLI 进程和 SQLite 写入，覆盖导入、自由文本提案、档案、确认、重启后检索、双会话预测、模型提案暂存、删除、证据移除后暂不建议、防重放与重置，不调用提供方。请选择新的私有目录。

[教程](tutorial.zh-CN.md)提供第二个可执行练习；原有结构化反馈演示 `scripts/demo_learning.py` 继续保留。

## 复现质量诊断

```sh
python3 -B scripts/evaluate_conversations.py
python3 -B scripts/evaluate_conversations.py \
  --holdout heldout-v2.json --manifest manifest-v2.json
```

默认数据目录是 `examples/evaluation`，`--holdout` 与 `--manifest` 传该目录内文件名。可用 `--output /path/outside/package/report.json` 保存新报告，不会覆盖已有文件。报告记录数据和源码哈希、覆盖率、输出条件下准确率、暂不建议、提取漏检及失败编号。

正常退出 0 表示评估完成，**不是所有质量案例通过**。加 `--require-all` 可用严格门槛，现有漏检会返回 1。不要改期望标签、削弱检查或丢弃失败案例来换取通过。

## 行为验收

| 路径 | 可观察证据 |
|---|---|
| 导入 | 本人与场景正确，只保留用户证据；重放不增加支持，改写或重排历史被拒绝 |
| 提取 | 原陈述、来源键与引文；引用、代码、临时内容按已测规则排除；确认前待审 |
| 档案 | 特征和例子描述导入消息，已确认偏好单独显示 |
| 提案审查 | 当前版本、真实决定、持久规则；纠正明确指定被替换规则 |
| 模型桥接 | 必须已知来源和精确引文；无效证据被拒，合法提案仍待审 |
| 预测 | 仅原始关系，限制每会话贡献，例子可查，弱证据与冲突暂不建议 |
| 删除 | 派生提案、规则、特征和关系移除；删 B 不生成 A→C；旧来源不能重放 |
| 暂停 / 重置 | 普通使用停止，导出删除可用，重置后暂停 |
| 宿主回复 | 真实回答使用已确认偏好，纠正后改变，与传输验收分开 |

公开收条使用合成数据。这些检查不能证明完整隐私识别、任意语义冲突解决、后台采集或跨设备同步。

## 保留的旧宿主与提供方证据

此前 2026-11-03 的 v0.3.0 工作执行过真实 MCP 管道与 Codex/Cursor 配置检查。一次 Codex 模型尝试加载规则后在 55 秒超时（退出 124，所属子进程已回收）；Cursor 加载规则后要求认证（退出 1），都没有取得已验收的模型回答。这些是历史尝试，**不是 v0.4.0 新模型验收**。

未宣称在线 DeepSeek API 或原生桌面 GUI 验收。生成上下文、配置和验证 MCP 调用是有用的本地检查，但不能认证模型行为或用户收益。

## 下一步应改进什么

使用新的独立数据改善改写覆盖，尤其英文；保留困难负例和场景变化。对比简单基线，同时报告建议了什么、漏掉什么。真实效用应在相似任务中比较采用偏好前后的回复，并请用户判断是否有帮助，不能把沉默当成认可。
