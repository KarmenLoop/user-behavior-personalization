### 已知案例与未见表达分开看

只有正确的 `ready_to_review` 候选才计入正例覆盖。选择不建议虽然可能更谨慎，但仍算漏掉正例。严格检查也会拒绝错误的额外建议；找到一项预期偏好，不能抵消另一项无关建议。

| 阶段 | 覆盖的正例 | 出现错误建议的负例 | 结果说明 |
|---|---:|---:|---|

| 较早修订版，原始集合 | 1/6 | 0/12 | 已知案例上的开发对照。 |
| 首次未见 `fresh-v2` 测试 | 0/8 | 0/14 | 保留的新表达失败记录。后来冻结的另一个版本在这个已知集合上达到 1/8。 |
| 首次未见 `fresh-v3` 测试 | 1/8 | 0/8 | 较早冻结识别器的独立结果，继续保留。 |

[v0.5.0 结果记录](evaluation-results-v0.5.0.json)保留源码和测试样本哈希、早期失败、开发对照、首次未见结果及其复现。全部案例均为合成数据，不能据此宣称已完成真实用户收益研究或具备不受限的语义理解能力。

### 复现当前习惯诊断

```sh
python3 -B scripts/evaluate_behavior.py --suite fresh-v4 --require-all
```

本版本**预期退出 1**，因为七个正例被漏掉。不带 `--require-all` 时退出 0 只表示诊断执行完成；退出 2 表示评估过程或源码完整性存在问题。使用 `--output /path/outside/package/new-report.json` 保存新报告，已有文件不会被覆盖。

`--suite initial`、`--suite fresh-v2` 与 `--suite fresh-v3` 现在使用的是已经暴露的回归数据。`--suite all` 同时包含已知案例与最初独立的新集合，不应合并成一个泛化分数。脚本验证冻结样本的哈希，只固定时钟；导入、持久状态、收集开关和习惯发现均通过真实本地宿主执行。用当前代码运行，不会自动还原历史源码版本。

## 复现保留的会话诊断

```sh
python3 -B scripts/evaluate_conversations.py
python3 -B scripts/evaluate_conversations.py \
  --holdout heldout-v2.json --manifest manifest-v2.json
```

默认数据目录是 `examples/evaluation`，`--holdout` 与 `--manifest` 传该目录内文件名。可用 `--output /path/outside/package/report.json` 保存新报告，不会覆盖已有文件。报告记录数据和源码哈希、覆盖率、输出条件下准确率、暂不建议、提取漏检及失败编号。

正常退出 0 表示评估完成，**不是所有质量案例通过**。加 `--require-all` 可用严格门槛，现有漏检会返回 1。不要改期望标签、削弱检查或丢弃失败案例来换取通过。

## 行为验收

| 路径 | 可观察证据 |
|---|---|
| 导入 | 本人与场景正确，只保留用户证据；重放不增加支持，改写或重排历史被拒绝 |
| 提取 | 原陈述、来源键与引文；引用、代码、临时内容按已测规则排除；确认前待审 |
| 档案 | 特征和例子描述导入消息，已确认偏好单独显示 |
| 提案审查 | 当前版本、真实决定、持久规则；纠正明确指定被替换规则 |
| 模型桥接 | 必须已知来源和精确引文；无效证据被拒，合法提案仍待审 |
| 预测 | 仅原始关系，限制每会话贡献，例子可查，弱证据与冲突暂不建议 |
| 删除 | 派生提案、规则、特征和关系移除；删 B 不生成 A→C；旧来源不能重放 |
| 暂停 / 重置 | 普通使用停止，导出删除可用，重置后暂停 |
| 宿主回复 | 真实回答使用已确认偏好，纠正后改变，与传输验收分开 |

公开收条使用合成数据。这些检查不能证明完整隐私识别、任意语义冲突解决、任意账号历史采集或跨设备同步。

## 下一步应改进什么

使用新的独立数据改善改写覆盖，尤其英文；保留困难负例和场景变化。对比简单基线，同时报告建议了什么、漏掉什么。真实效用应在相似任务中比较采用偏好前后的回复，并请用户判断是否有帮助，不能把沉默当成认可。
