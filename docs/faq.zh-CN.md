# 二十个实际使用问题 — v0.3.0

[English](faq.en.md) · [中文](faq.zh-CN.md)

## 1. 助手怎样学习我的工作习惯？

明确偏好可以直接保存。开启观察后，宿主可把已授权反馈记录为带场景、来源和会话的事件。适配器审查证据后才提出候选，是否成为默认习惯由你决定。

## 2. 它能知道我在想什么吗？

不能。它可以解释已经观察到的协作规律，在熟悉场景里建议下一步；不能断言私密动机、预测所有决定或读取思想。证据不足或冲突时，不应采用新的推断。

## 3. 不上传聊天记录也能用吗？

可以。本地练习、存储、审查和隐私工具不需要联网。若连接云模型，选定规则和任务仍会按宿主自己的策略发送；适配器不会爬取或上传完整历史。

## 4. 它究竟记住哪些内容？

明确规则，以及关于回答长度、结构、教学方式、主动程度、下一步流程和语言的结构化反馈。明确规则由宿主提供来源与最小摘要，不需要完整聊天库或心理标签。

## 5. 工作和私人偏好怎样分开？

身份和权限需要隔离时，使用不同 subject 或独立数据根。同一用户内使用 code-review、travel-planning 等稳定场景名，完整匹配并忽略大小写；规则的 * 表示明确的全局范围。

## 6. Codex 和 Cursor 能共用偏好吗？

同一台机器上，两者配置相同私有根和正确绑定的 subject，即可读取相同已提交档案。这不会关联线上账号，也不会同步另一台设备。

## 7. DeepSeek 能直接连接这个 MCP 服务吗？

聊天 API 本身不是 MCP 客户端。可用 build_context.py 为自己的聊天客户端生成带场景偏好的 messages；工具调用还需白名单桥接与用户授权。本版本没有内置在线 DeepSeek 工具循环。

## 8. 与系统提示或自定义说明有什么区别？

提示词可以承载偏好，但本身不提供来源跟踪、版本、场景检索、审查和删除。适配器补上这些操作，宿主仍负责在指令层级内加载结果。

## 9. 这是 RAG、微调或新模型吗？

都不是。这是结构化偏好记忆和确定性的审查流程。修改档案不训练权重、不增加模型上下文长度，也不会把全部聊天建立成向量索引。

## 10. 为什么至少需要三个会话？

这是防止把一次反应当成长期习惯的工程限制，还需满足时间加权支持和近期支持条件。它不是统计或心理学保证。

## 11. 重复发送同一条消息会提高分数吗？

相同来源重放会去重；同一场景和维度中，一个会话只计最新观察。宿主不能伪造来源或会话 ID，适配器无法独立核实现实互动是否存在。

## 12. 我改变想法时怎么办？

用新来源和当前版本纠正原规则。当前任务中的临时要求仍优先于旧默认。新反馈可以反对旧规律，但已确认规则应明确审查或纠正，不能静默改写。

## 13. 为什么有时不推荐新的偏好？

独立会话太少、证据过旧、反对证据、已有适用的明确偏好，都可能阻止推荐。用 profile_insights 查看真实理由；暂不判断是正常结果。

## 14. 它能模仿我的写作吗？

能采用已确认的语言、长度和结构选择，但不会复制身份、克隆私有作品库或保证完整模仿。风格要求不应扩展为对整个人的判断。

## 15. “费曼式学习”或解释回述怎么用？

用户可以选择用自己的话解释概念、看例题或做练习。课程由宿主提供，适配器保存已确认的方式偏好。这是教学互动，不是人格测评。

## 16. 建议下一步后会自行行动吗？

不会。workflow_next_step 可以建议实现后测试、交付前审查，但不会因此调用工具、发消息、购买或增加权限。

## 17. 怎样停止学习但保留已有数据？

使用 profile_pause，普通检索与学习停止，导出和删除继续可用。如需从配置层关闭新增观察，再移除 --enable-observations。这两种操作本身都不删除已有内容。

## 18. “遗忘”会从所有地方彻底删除吗？

它删除指定受控内容、关联学习数据和受控产物，并保留最小来源哈希防重放。复制出去的导出、旧版未绑定输出、提供方日志和外部备份需另行清理，不承诺物理擦盘。

## 19. 为什么写入提示版本过期？

你读取之后发生了另一笔更新。先读取当前版本并查看变化，再决定是否重新提交；不要盲目重试或覆盖更新的用户纠正。

## 20. 怎样确认助手确实变好用了？

先走本地教程，再用合成数据检查真实宿主回复、更正和删除。比较相似任务，看看是否减少了反复纠正格式。本地测试与支持度都不能证明满意度，具体方法见验收指南。
